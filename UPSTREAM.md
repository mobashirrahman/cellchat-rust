# Upstream pin

All parity oracles, benchmarks and error messages in this project refer to exactly one
upstream state. Re-pinning is a deliberate, reviewed act (it invalidates the oracle suite
and requires regenerating it), never an automatic one.

## Verify

```sh
git clone https://github.com/jinworks/CellChat && cd CellChat
git rev-parse HEAD   # must print 75253cd0c9e68410e6e721a6d3a0419a1d7e358f
grep Version DESCRIPTION
```

`tests/parity/manifest.json` records this SHA for every stored oracle, and
`tests/parity/test_pin.py` fails if the local checkout does not match.

  `docs/SEMANTICS.md` (in particular R-ism 11, the missing-subunit crash, which we

## Packaging notes

* `R CMD check` is **Status: OK** on the tarball from `R CMD build`, with the R tests run.
  Three things had to be got right, and each is a trap rather than a typo:
  * `src/` needs at least one source file or check warns, but *any* compiled object makes R
    link `cellchatrs.so` and **overwrite** the Rust cdylib `./configure` staged, after which
    the package fails to load with `no such symbol wrap__make_cellchatrs_wrappers`. The
    resolution is a stub `.c` plus `OBJECTS =` in `src/Makevars`; see that file.
  * `SHLIB` cannot be renamed from a package `Makevars` -- R's `Makeconf` wins -- so
    renaming the link target is not an available workaround.
  * The three multi-megabyte Rust golden corpora are excluded by `.Rbuildignore`; they take
    the tarball from 24 MB to 0.73 MB, under CRAN's 5 MB source limit. They are cargo-test
    inputs, not R-test inputs, and `scripts/gen_fixtures.sh` regenerates them.
* `man/` is generated by `scripts/gen_man.py` from the roxygen blocks in `R/*.R`, because
  `roxygen2` is not installable here (`pkgload` fails to build). `\usage` is read from each
  function's own formals via R, so a signature change cannot desynchronise it -- `R CMD check`
  compares the two and would otherwise fail.
