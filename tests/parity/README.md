# Parity corpora

Every `.txt` / `.tsv` file here is **generated**, never hand-edited. Each has a `gen_*.R`
(or `gen_f80_ref.c`) script in this directory that produces it from the pinned upstream
commit. Regenerate all of them with:

```sh
export CELLCHAT_SRC=/path/to/CellChat   # clone at 75253cd0c9e68410e6e721a6d3a0419a1d7e358f
R_LIBS=.rlib R --vanilla -f tests/parity/gen_rng_golden.R
R_LIBS=.rlib R --vanilla -f tests/parity/gen_rng_stress.R
R_LIBS=.rlib R --vanilla -f tests/parity/gen_stats_golden.R
cc -O2 -o /tmp/f80_ref tests/parity/gen_f80_ref.c -lm && /tmp/f80_ref > tests/fixtures/f80_ref.txt
R_LIBS=.rlib R --vanilla -f tests/parity/export_db.R
R_LIBS=.rlib R --vanilla -f tests/parity/gen_expr_golden.R
R_LIBS=.rlib R --vanilla -f tests/parity/gen_prob_golden.R
```

## The rule that keeps biting: dump the inputs, do not re-derive them

Three times now, a Rust test tried to reconstruct a fixture from `set.seed` / `runif` and
got it subtly wrong. The failures had a distinctive shape: **the gene *set* stayed correct
while the *values* permuted**, so every name still resolved, every value was still
plausible, and only a bit-level comparison caught it. Two of the three were R ordering
rules (`unlist()` on a data-frame column slice is column-major; `aggregate()` is
group-major and its `t()` is a real transpose).

So the fixtures now contain the inputs verbatim:

| file | what | why it is a file |
|---|---|---|
| `expr_matrix.tsv` | the 416 x 6 `computeExpr` matrix, `%a` hex floats | re-deriving it required reproducing `unlist()`'s column-major order |
| `prob_inputs.tsv` | the cell matrix, group labels, cell groups, L-R table | same reason, plus a hand-built L-R table |
| `prob_avg.txt` | R's own `data.use.avg` for each configuration | otherwise a bug in the aggregation would cancel out on both sides |

Each is **self-describing** (`groups<TAB>n`, `genes<TAB>m`, a `values` marker) rather than
inferred from line counts — R's connection buffering reordered two halves of a file once,
and a reader that infers the layout cannot tell that from corruption.

Hand-transcribed tables (`LR_DF` in `expr_parity.rs`, the config list in `prob_parity.rs`)
are checked against a record the generator emits for the purpose, so drift is loud.

And the end-to-end gate, which is the acceptance criterion from the objective:

```sh
R_LIBS=.rlib R --vanilla -f tests/parity/check_identical.R
```

This runs the **installed R shim** and the **pinned upstream body** on the same objects and
requires `identical()` on `net$prob`, `net$pval`, `dimnames` and `options$parameter`, plus a
byte-for-byte match on `match.arg` error messages. 33 comparisons over 9 configurations.
`options$run.time` is excluded: it is wall-clock and cannot be identical by construction.

## `check_rust_path.R`

Proves the Rust kernel is actually reached, from outside the package.

A differential gate cannot tell "the port matches" from "the port was never called". That is not
hypothetical: `computeCommunProb` gated its Rust path on
`nzchar(Sys.getenv("CELLCHATRS_FALLBACK", "0"))`, and `"0"` is four characters, so the predicate
was always true and a fully green run had been comparing upstream with itself.

The two paths are made distinguishable from the outside: the Rust path resolves its database
through `cellchatrs_db_dir`, which *requires a readable directory*, while the upstream path uses
`object@DB` and never looks at a directory. Point `options$db` at a directory that does not exist
and the Rust path must fail with `no CellChatDB export found`; if the call succeeds, it did not
reach the kernel.

Run it with `CELLCHATRS_DB` **unset** -- the probe deliberately does not set it, because
`cellchatrs_db_dir` falls back to it and the bogus path would then resolve.

## `exact_neighbour_oracle.R`

Upstream's `computeRegionDistance` body, with two expressions replaced by exhaustive search. Shared
by `gen_region_golden.R` (which runs it over the corpus layouts) and `check_identical.R` (which
installs it into the pinned-upstream environment so the spatial branch of `computeCommunProb` can
run at all).

One copy, because two copies that drifted would be different functions with the same name and the
gate would compare the port against an accident. The corpus generator records each layout's
neighbour margin so the substitution is checked rather than asserted; the gate's layouts rely on
the same construction but do not record it, which is a real asymmetry between the two uses.
